3 Approaches สำหรับ Layout Improvement

สรุปสิ่งที่ต้องทำ: fix overflow mobile landscape + tablet portrait grid + tablet landscape 2-col ขยาย

Requirements สรุป
📱 Mobile Landscape (600–767px)
  • Fix BotPnL/Heatmap overflow
  • Right panel ปัจจุบัน 240–320px → ขยายเป็น 34–38%
  • BotPnL+Heatmap fluid height
📱 Tablet Portrait (768–1023px portrait)
  • 2-col card grid overview
  • Tap card → detail view
  • Layout ใหม่ทั้งหมด
📱 Tablet Landscape (768–1023px landscape)
  • 2-col, right panel 38%
  • BotPnL+Heatmap side-by-side
  • ปรับจาก landscape ปัจจุบัน
A

CSS-first — แยก breakpoint + orientation query (แนะนำ)

แยก breakpoint 600–1023px ออกเป็น 3 ส่วน ใช้ CSS media query ร่วมกับ orientation — JS เพิ่ม state แค่ isTabletPortrait และ isTabletLandscape

/* เดิม */
600–1023px → account-card--landscape

/* ใหม่ */
600–767px → account-card--landscape (fix overflow)
768–1023px + portrait → account-card--tablet-portrait (grid)
768–1023px + landscape → account-card--tablet-landscape (2-col wide)
ข้อดี
  • แก้ JS น้อย — เพิ่ม 2 state
  • CSS ควบคุม visual ทุกอย่าง
  • Pattern เดิม — ง่าย maintain
  • Orientation change smooth
ข้อระวัง
  • Tablet portrait grid ต้องเขียน JSX ใหม่
  • CSS เพิ่มขึ้น ~80 lines
B

React-state-driven — layout tier per state

เพิ่ม layoutTier state: "mobile" | "landscape" | "tablet-portrait" | "tablet-landscape" | "desktop" — แต่ละ tier render JSX แยกกันสมบูรณ์ใน AccountCard

// DashboardClient.tsx
if (tier === "tablet-portrait") return <TabletPortraitGrid />
if (tier === "tablet-landscape") return <TabletLandscapeCard />
if (tier === "landscape") return <LandscapeCard />
ข้อดี
  • แต่ละ tier ชัดเจน — ไม่พัง tier อื่น
  • ง่าย extend ในอนาคต
ข้อระวัง
  • Code ซ้ำกันมากระหว่าง tier
  • DashboardClient.tsx ใหญ่ขึ้นมาก
  • Refactor ใหญ่กว่า approach A
C

Hybrid — CSS-first + แยก TabletPortraitOverview component

Approach A สำหรับ landscape + tablet landscape (CSS เท่านั้น) แต่ tablet portrait ใช้ component ใหม่แยก TabletPortraitOverview.tsx ที่ mount แทน account list ปกติ

// DashboardClient.tsx (root level)
if (isTabletPortrait) return <TabletPortraitOverview accounts={...} />
// ไม่กระทบ AccountCard เดิมเลย
ข้อดี
  • Portrait grid แยกสะอาด — ไม่แตะโค้ดเดิม
  • Landscape fix ง่าย ไม่ซับซ้อน
  • Best isolation สำหรับ portrait tier
ข้อระวัง
  • Logic แยก 2 ที่ (DashboardClient + TabletPortraitOverview)
  • ต้อง sync data fetching ให้ดี
⭐ คำแนะนำ: Approach C (Hybrid)

แยก TabletPortraitOverview component ออกจากโค้ดเดิมสำหรับ portrait grid (isolation สูง) + ใช้ CSS-only สำหรับ landscape/tablet landscape fixes (เสี่ยงต่ำ) — ได้ทั้ง clean isolation และ minimal disruption ในจุดเดียว
