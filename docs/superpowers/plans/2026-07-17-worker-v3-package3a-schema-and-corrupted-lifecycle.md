# Package 3a: WorkerMessageFailure Schema + Corrupted-Lifecycle Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lay the schema and pure-function groundwork for Package 3 (durable Worker V2 ingestion, see `docs/superpowers/plans/2026-07-16-history-first-dashboard-worker-v3.md`) without touching the deal-consumer's transaction/XACK ordering: add the `WorkerMessageFailure` table and a `BridgeHistoryChunk.reconstructionAlgorithmVersion` column via migration, and teach `computePositionLifecycle` in `src/worker-v2/position-reconstructor.ts` to return a distinguishable `"corrupted"` status for missing price, missing symbol, and unknown trade direction — instead of silently falling through to `"open"` — so a later plan (Package 3b) can route these to `WorkerMessageFailure` instead of ever emitting a guessed `Position`.

**Architecture:** Two independent, testable pieces. Task 1 is a pure Prisma schema migration (additive only — no existing column touched, no data migration needed). Task 2 is a pure-function change to `computePositionLifecycle` (no I/O, already covered by `position-reconstructor.test.ts`) that adds a new `PositionLifecycleResult` variant and three new detection branches. Neither task wires anything into `deal-consumer.ts` — `reconstructPositionIfClosed` continues to no-op (return without writing) on every non-`"closed"` status exactly as it does today; only the set of possible non-`"closed"` statuses grows. Wiring `"corrupted"`/`"ambiguous-reopen"` results into actual `WorkerMessageFailure` rows (with real `streamId`/`chunkId`/`ordinal` for idempotency) is Package 3b's job, once the envelope/transaction port exists to provide those values.

**Tech Stack:** Prisma 6 + PostgreSQL 15, TypeScript, `node:test` + `node:assert/strict`, `Prisma.Decimal` for money fields.

## Global Constraints

- Money fields use `Prisma.Decimal` with `@db.Decimal(28, 8)`, matching every existing money column in `prisma/schema.prisma` (e.g. `Deal.profit` at line 190).
- Net P/L is always `profit + swap + commission` — `fee` is tracked but excluded from every net P/L sum (see `CLAUDE.md` "Source boundaries" section and `computePositionLifecycle`'s existing `netPnl` line). Do not add `fee` back anywhere in this plan.
- Timestamp columns use `DateTime @db.Timestamptz(3)`, matching `BridgeHistoryChunk`'s `createdAt`/`updatedAt`/`completedAt` columns (schema.prisma lines 256–258).
- New Prisma models use `@map("snake_case_column")` per field and `@@map("PascalCaseTableName")` on the model, matching every existing model in `prisma/schema.prisma`.
- Never emit a guessed `Position`/`ClosedPosition` row for a lifecycle that cannot be fully resolved (missing price, missing symbol, unknown direction, or reopen-after-close). `reconstructPositionIfClosed` must keep returning without writing for every status other than `"closed"`.
- Run `npx prisma generate` after any schema change, before running tests that import `@prisma/client` types.
- Full verification baseline before considering a task done: `node --import tsx --test src/worker-v2/position-reconstructor.test.ts`, `npm run lint`, `npx tsc --noEmit`.

### Task 1: Add `WorkerMessageFailure` model and `BridgeHistoryChunk.reconstructionAlgorithmVersion` column

**Files:**
- Modify: `prisma/schema.prisma`
- Create: `prisma/migrations/<timestamp>_add_worker_message_failure/migration.sql` (auto-generated by `prisma migrate dev`, not hand-written)

**Interfaces:**
- Produces: `WorkerMessageFailure` Prisma model — used by Package 3b to persist unresolved lifecycle/ingestion failures. Fields: `id` (cuid PK), `tradingAccountId` (FK to `TradingAccount`), `streamId` (nullable string — Redis stream entry ID, set once the failure is tied to a specific message), `chunkId` (nullable string — `BridgeHistoryChunk.id`, set once known), `errorCode` (string — short machine-readable reason, e.g. `"missing-price"`, `"missing-symbol"`, `"unknown-direction"`, `"ambiguous-reopen"`), `payload` (`Json` — the raw failing record for operator inspection), `attempts` (int, default 1), `resolved` (bool, default false), `resolvedAt` (nullable timestamptz), `createdAt`/`updatedAt` (timestamptz).
- Produces: `BridgeHistoryChunk.reconstructionAlgorithmVersion` (`Int @default(1)`) — records which version of `computePositionLifecycle`'s algorithm produced a chunk's derived positions, per Package 3's "Store derived Position count/digest and reconstruction algorithm version before checkpoint advancement" requirement. Position count/digest already exist as `positionsExpectedCount`/`positionsAppliedCount`/`positionsAppliedDigest` on the same model (schema.prisma lines 246–248) — reused as-is, not duplicated.

## Out of Scope (deferred to Package 3b)

- Wiring `"corrupted"`/`"ambiguous-reopen"` results into actual `WorkerMessageFailure` rows. This plan only makes the table exist and makes the statuses distinguishable; nothing yet writes to `WorkerMessageFailure`. Doing so meaningfully requires a `streamId`/`chunkId`/ordinal to form a stable idempotency key (so repeated deals against the same corrupted position don't create unbounded duplicate failure rows), and those values only exist once Package 3b's envelope/transaction port is in place.
- Any change to `src/worker-v2/deal-consumer.ts`, stream envelope shape, ordinal/digest/barrier handling, or XACK ordering — all Package 3b.
- Any change to worker-v3's mirror of `position-reconstructor.ts` (`src/worker-v3/processors/position-reconstructor.ts`) — worker-v3 is unwired scaffolding (confirmed via prior ponytail-audit: no docker-compose entry, no build target, no external callers) and duplicating this fix there now would be premature; port it when worker-v3 migration actually proceeds, per the existing [[project_worker_v3_rename_plan]] memory note.
